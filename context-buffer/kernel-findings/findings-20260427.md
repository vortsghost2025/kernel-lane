## 1. matrix_tensor_async Grid-Dimension Y Error — Diagnosis & Fix

**Error:** `cudaErrorInvalidValue` with message "Grid Dimension Y must be nonzero" detected by compute-sanitizer during `matrix_tensor_async.exe` launch.

### Root Cause

The binary accepts up to four positional arguments: `M N K mode`. When invoked with only a mode string (e.g., `matrix_tensor_async.exe fp16`), `std::atoi("fp16")` returns `0`, causing `M = 0`. The grid Y dimension is computed as:

```cpp
dim3 grid((N + WMMA_N - 1) / WMMA_N, (M + 63) / 64);
```

With `M = 0`, `grid.y = (0 + 63) / 64 = 0` via integer truncation, violating CUDA's requirement that all grid dimensions be > 0.

### Evidence

- Compute-sanitizer summary: `profiles/headless/compute-sanitizer-summary.txt`
- Inbox task references: `task-20260428-strict-review-kernel.json`, `20260426210234-archivist-caisc-prep.json`
- Source file: `kernels/src/matrix_tensor_async.cu`

### Fix Implemented

Added argument validation in `main()` to reject zero or negative dimensions before kernel launch:

```cpp
if (M <= 0 || N <= 0 || K <= 0) {
    std::cerr << "Error: invalid matrix dimensions (must be > 0). Got M=" << M
              << " N=" << N << " K=" << K << std::endl;
    std::cerr << "Usage: " << argv[0] << " [M] [N] [K] [mode]" << std::endl
              << "  M: matrix rows (default 1024)" << std::endl
              << "  N: matrix cols (default 1024)" << std::endl
              << "  K: inner dimension (default 1024)" << std::endl
              << "  mode: fp16 or fp8 (default fp16)" << std::endl;
    return 1;
}
```

This converts an opaque CUDA launch error into a clear usage error, prevents the invalid launch, and guides the user toward correct invocation.

### Verification Recommendation

Rebuild the binary and re-run compute-sanitizer:
```powershell
.\scripts\build-kernels.ps1
compute-sanitizer --tool memcheck kernels/bin/matrix_tensor_async.exe
```

Expected: clean memcheck (no grid-dimension errors).
